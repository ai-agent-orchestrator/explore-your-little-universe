최종 자동 테스트는 **Python 35개(실제 저장소 통합 테스트 7개 포함), 프런트 13개**, 모두 통과했다. 기존 HTTP 16유형과 한국어 검색 점검 10문항도 통과했다. [타로 30문항 기록](TAROT_RETRIEVAL_CHECKS.json)은 카드·방향 필터 커버리지 점검이며 관련성이나 LLM 품질의 정답률이 아니다.

생성·의미 검수는 **FakeLLM만 검증**했다. 실제 LLM 엔드포인트·키를 사용하지 않았다. 기본 서버를 직접 시작해 `postgres/neo4j/chroma/embedding=ok`, `llm=missing`인 상태에서도 health가 정상 제공되는 것을 확인했다. 실제 LLM을 미설정한 실행을 Fake 성공으로 바꾸지 않는다.

실제 PostgreSQL은 공식 EDB 17.12 바이너리로 127.0.0.1:5433에서 시험했다. Docker가 없어 compose 기동은 검증하지 않았다. 실제 모바일 기기 성능·외부 LLM 서비스 호환성과 응답 품질·운영 부하와 장기 보관 정책은 이번 검증에 포함하지 않았다.

## 명세를 구체화한 부분

- `RAW_CARDS`의 공개 경로 `mbti_lab.scenarios.RAW_CARDS`는 유지한다. 순환 없는 의존 방향을 위해 실제 상수는 `lumi_core.corpus.original`에 두고 같은 객체를 재노출한다.
- 기존 일상 청크에는 `facet` 키가 없으므로 `Chunk.facet`은 선택 필드다. 키를 덧붙여 R0의 직렬화 결과를 바꾸지 않았다.
- 최초 생성 응답 유실 시 토큰은 아직 클라이언트에 없고, DB에도 해시만 있으므로 원래 토큰을 복원해 반환할 수 없다. bootstrap 키 해시로 중복 뽑기를 막고 `409 session_token_required`로 안내한다. 토큰을 받은 이후의 재확인은 같은 토큰·키로 같은 세션을 반환한다.
- `health.llm=ok`는 설정과 클라이언트 준비 상태다. 유료 검증 호출을 health에 넣지 않았다.
- 카드별 출처가 없으면 LLM 생성 호출 전 종료한다. 일반 MBTI·별자리 글을 해당 카드의 누락 근거 대신 사용하지 않는다.
- 역방향을 부정적 결과로 일괄 분류하지 않는다. 출처 있는 직접 작성 규칙에 `amplifies`, `balances`, `contrasts`를 두며, 상징적 대조를 실제 인과로 표현하지 않는다.
